# Core Order POS — Text Mode

โปรแกรม Console ภาษาไทยตามภาพคลาสทั้ง 7 และกติกาธุรกิจที่ผู้ใช้ยืนยัน ใช้ Java 17 ขึ้นไปและไลบรารีมาตรฐาน ข้อมูลเก็บใน data/pos-data.bin ข้างโฟลเดอร์ที่เปิดโปรแกรม

## เปิดโปรแกรม

ดับเบิลคลิก **run.cmd** หรือเปิด PowerShell:

~~~powershell
cd 'D:\workปี3\Codex\pos-console'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
~~~

สคริปต์ค้นหา JDK 17+ จาก JAVA_HOME, javac และ JDK ที่มากับส่วนขยาย Java ของ VS Code เครื่องนี้ใช้ JDK 21 จากส่วนขยาย Java คอมไพล์เป็น Java 17 ด้วย --release 17 โดยไม่เปลี่ยนการตั้งค่า Java ของเครื่อง สคริปต์ใช้พาธสัมพัทธ์เมื่อเรียก Java เพื่อรองรับโฟลเดอร์ภาษาไทย

ระบุ JDK เองได้ด้วย:

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -JdkHome 'C:\Program Files\Java\jdk-17'
~~~

ต้องมีทั้ง java.exe และ javac.exe ใช้ Windows Terminal/ฟอนต์ที่รองรับภาษาไทย โปรแกรมอ่านเขียน UTF-8 และ run.cmd ตั้ง code page 65001

## เมนูและความสามารถ

| เมนู | การทำงาน |
|---|---|
| 1 ขายสินค้า | เลือกลูกค้า เลือกไอศกรีม/ภาชนะ ขนาดและรส ใช้คะแนน และรับเงินสดหรือ QR จำลอง |
| 2 จัดการออร์เดอร์ | ดูวันเวลาและต้นทุน เปิดออร์เดอร์/ชำระเงิน เริ่มจัดเตรียม ส่งมอบ หรือยกเลิกพร้อมเหตุผล |
| 3 สมาชิก | สมัคร ค้นหา ตรวจคะแนน แก้ชื่อ/เบอร์ รายชื่อ และเมนู 5 ประวัติได้รับ/ใช้/คืน/ตั้งต้น |
| 4 วัตถุดิบ | ดูคงเหลือและเกณฑ์เตือน รับล็อตพร้อมต้นทุน/เหตุผล ลดรายล็อตพร้อมเหตุผล ดูล็อต/ประวัติลด เพิ่มชนิดวัตถุดิบ |
| 5 รายงาน | เลือกทั้งรอบหรือช่วงวันที่ ยอดรับชำระ คืนเงิน ต้นทุนสุทธิ กำไรขั้นต้น และสินค้าขายดี 5 อันดับ |
| 0 ออก | ปิดโปรแกรม |

### ไอศกรีมเลือกขนาดและรสชาติ

ในเมนูขาย เลือกเพิ่มสินค้าเพื่อเปิดเมนูไอศกรีม เลือกถ้วย, โคนวาฟเฟิล หรือถ้วยวาฟเฟิล พร้อมขนาดและจำนวนรสตามตารางในภาพ จากนั้นเลือกรสได้หลายรสโดยไม่ซ้ำ ระบบจะคิดราคาและตัดสต็อกแยกรสพร้อมภาชนะ

กด 0 ในหน้ารายการก่อนชำระเพื่อทิ้งออร์เดอร์ที่ยังไม่จ่ายและกลับเมนูหลัก ระบบไม่เก็บร่างไว้ทำต่อ

รสชาติ 15 รายการ: คาราเมลแครก, คุกกี้แอนด์ครีม, ชีส, นมข้นน้ำผึ้ง, โยเกิร์ตสตรอเบอร์รี่ชีสเค้ก, มิ้นช็อคชิพ, อูจิมัทฉะ, นมเปรี้ยวปีโป้, เชอร์รี่เบอร์รี่ชอร์เบย์, มิกซ์แอปเปิ้ล, นมเมล่อน, มอคค่าอัลมอนด์, ช็อกโกแลต, รัมเรซิ่น และบลูเบอร์รี่โยเกิร์ต

พนักงานสาธิต E001 มีชื่อและบทบาท “พนักงานเคาน์เตอร์” ไม่มีระบบเข้าสู่ระบบหรือกำหนดสิทธิหลายผู้ใช้ เงินและต้นทุนใช้ BigDecimal ราคา/เงินในเมนูรองรับทศนิยม 2 ตำแหน่ง วัตถุดิบรองรับ 3 ตำแหน่ง จำนวนสินค้าต่อรายการ 1–10,000 เมนูที่ป้อนค่าผิดจะให้กรอกใหม่หรือแจ้งเหตุผลแล้วกลับทำงานต่อ

## ข้อมูลสาธิตและการลองขาย

สมาชิก **0812345678** เริ่มด้วย 100 คะแนนและมีรายการ “ตั้งต้นสาธิต” ในประวัติ สมาชิกสมัครใหม่เริ่มที่ 0 คะแนน ชื่อสมาชิก/เบอร์และรหัสลูกค้า/รหัสสมาชิกแยกกัน

| สินค้า | ราคา | สูตรต่อหน่วย | ต้นทุนสาธิตเริ่มต้น |
|---|---:|---|---:|
| วานิลลาโคน 1 สกู๊ป | 30 บาท | วานิลลา 1 + โคน 1 | 10 บาท |
| ช็อกโกแลตโคน 1 สกู๊ป | 35 บาท | ช็อกโกแลต 1 + โคน 1 | 12 บาท |
| โคนสองรส | 55 บาท | วานิลลา 1 + ช็อกโกแลต 1 + โคน 1 | 20 บาท |

วานิลลาล็อตแรก 8 บาท/สกู๊ป ล็อตถัดไป 9 บาท/สกู๊ป ช็อกโกแลตล็อตใช้ได้ 10 บาท/สกู๊ป โคน 2 บาท/ชิ้น ตัวเลขเป็นข้อมูลสาธิตทั้งหมด วันที่รับเข้า/หมดอายุสัมพันธ์กับวันเปิดโปรแกรมประเทศไทย มีล็อตหมดอายุ ใกล้หมดอายุ และสต็อกเหลือน้อยสำหรับลองคำเตือน ราคาขายเป็นราคาสุดท้าย ไม่เพิ่มภาษี/ค่าบริการ

1. เมนู 1 → เป็นสมาชิก → กรอก 0812345678
2. เพิ่มไอศกรีมขนาด M ราคา 39 บาท แล้วเลือกรสชาติได้ 1–3 รส
3. ใช้ 10 คะแนน → ลด 10 บาท เหลือ 29 บาท
4. ชำระเงินสด 100 บาท → ยืนยัน → ทอน 71 บาท และตัดสต็อกตาม FIFO
5. เมนู 2 → เลือกออร์เดอร์ → เริ่มจัดเตรียม → ส่งมอบ ได้คะแนนจากยอดสุทธิ
6. เมนู 3 → 5 ดูประวัติ หรือเมนู 5 → 1 ดูรายงานยอดขาย

ถ้าจะลองคืนเงิน ให้ยกเลิกหลังชำระ **ก่อนเริ่มจัดเตรียม** และระบุเหตุผล ระบบคืนเงิน 35 บาท คืน 20 คะแนน และวัตถุดิบเข้าล็อตเดิม ยอดสุทธิและต้นทุนสุทธิของรอบกลับเป็น 0

QR เป็นการจำลอง พนักงานยืนยันว่าได้รับเงินครบ ไม่มีการสร้าง QR เชื่อมธนาคาร ตรวจธุรกรรมหรือคืนเงินจริง

## กติกาที่สำคัญ

- สถานะ: รอชำระ → รอจัดเตรียม → กำลังจัดเตรียม → เตรียมเสร็จ → ส่งมอบ หรือยกเลิกก่อนเริ่มทำ ร่างไม่ตัดสต็อก/คะแนนและไม่นับยอดขาย
- ตรวจชำระครบ คะแนนปัจจุบัน และวัตถุดิบทั้งออร์เดอร์ก่อนเปลี่ยนข้อมูล การวางแผน FIFO เก็บยอดจองไว้ในแผนชั่วคราว หากรายการใดไม่พอ ข้อมูลจริงยังเหมือนเดิม
- ใช้คะแนนเป็นชุดละ 10 ลดชุดละ 10 บาท ไม่เกินคะแนนที่มีหรือยอดสินค้า ไม่แลกเงินสด เพิ่มคะแนนเมื่อส่งมอบจาก floor(ยอดสุทธิ/10) เพียงครั้งเดียว
- ยกเลิกต้องมีเหตุผล เฉพาะร่างหรือชำระแล้วแต่ยังรอจัดเตรียม คืนเงินสุทธิที่จ่าย ไม่รวมเงินทอน คืนคะแนนที่ใช้และสต็อกครั้งเดียว เก็บประวัติเดิมไว้
- ล็อต FIFO เรียงวันรับเข้า วันเดียวกันใช้ลำดับเพิ่มล็อต ข้ามล็อตหมดอายุหรือยังไม่ถึงวันรับเข้า ใช้ได้ถึงวันหมดอายุ วันถัดไปห้ามใช้
- คืนสต็อกเข้าล็อตเดิม แม้หมดอายุแล้ว ล็อตที่คืนแล้วหมดอายุยังห้ามใช้ขาย
- เตือนเมื่อสต็อกใช้ขายได้ต่ำกว่า 50% ของสต็อกปกติ เท่ากับ 50% ไม่เตือน เตือนก่อนหมดอายุ 0–3 วัน แยกข้อความหมดอายุ ไม่เตือนล็อตว่าง
- รับล็อตจากหน้าจอห้ามวันรับเข้าอนาคต วันหมดอายุห้ามก่อนรับเข้า จำนวนต้องมากกว่า 0 ต้นทุนไม่ติดลบ เหตุผลรับเข้าเก็บกับล็อต ลดด้วยมือต้องมีเหตุผลและห้ามลดเกินจำนวนล็อต
- ออร์เดอร์เก็บชื่อ/ราคา/สูตร ณ ตอนเลือกสินค้า แก้สินค้าแล้วไม่เปลี่ยนรายการเดิม ต้นทุนจริงบันทึกตอนชำระจากล็อตที่ตัดแต่ละรายการ
- ต้นทุนประมาณการสินค้าใช้ FIFO ปัจจุบันสำหรับหนึ่งหน่วย เป็นการอ่านอย่างเดียว ไม่จอง/ลดสต็อก หากสูตรไม่ครบให้แจ้งว่าคำนวณไม่ได้

## รายงานวันที่ ต้นทุน และกำไร

ช่วงวันที่รวมวันเริ่มและวันสิ้นสุด ใช้วันชำระสำหรับยอดขาย/ต้นทุน และวันยกเลิกสำหรับเงินคืน/ต้นทุนคืน เวลาใช้ประเทศไทย

ยอดสุทธิ = ยอดรับชำระ − เงินคืน  
ต้นทุนสุทธิ = ต้นทุนล็อตที่ขาย − ต้นทุนเดิมของล็อตที่คืน  
กำไรขั้นต้น = ยอดสุทธิ − ต้นทุนสุทธิ

ถ้าขายวันที่ 7 และคืนวันที่ 8 รายงานวันที่ 7 ยังเป็นยอดขายเดิม วันที่ 8 มีรายการกลับยอด จึงติดลบได้ การคืนไม่ย้อนย้ายรายการไปวันขาย รายงานทั้งช่วงสองวันรวมเป็น 0

จำนวนออร์เดอร์ชำระนับวันชำระ จำนวนยกเลิกหลังชำระนับวันยกเลิก จำนวนส่งมอบคือสถานะปัจจุบันของออร์เดอร์ที่ชำระในช่วงรายงาน ยอดก่อนลดและส่วนลดเป็นประวัติออร์เดอร์ชำระ ไม่ลบเมื่อคืนเงิน เงินทอนไม่ใช่รายได้

สินค้าขายดีนับจำนวนขายลบจำนวนคืนในช่วงเดียวกัน แสดงเฉพาะจำนวนสุทธิมากกว่า 0 เรียงจำนวนจากมากไปน้อยและรหัสสินค้าเมื่อเท่ากัน ชื่อในอันดับใช้ชื่อสินค้าปัจจุบัน ส่วนชื่อในออร์เดอร์เป็นชื่อที่บันทึกไว้ตอนสั่ง กำไรยังไม่รวมค่าแรง ค่าเช่า หรือค่าใช้จ่ายร้าน
